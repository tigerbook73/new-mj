# 杭州麻将规则（rulesetId: `hangzhou`）

> 状态：v3 定稿，已实现并测试通过（`packages/core/src/rulesets/hangzhou/`）。规则来源为用户提供的"边锋杭州麻将规则总结"；原始规则里未给出的细节已与用户逐条确认，拍板记录见 §14。
> 本文件内聚杭州麻将的全部知识：规则、专属类型、专属事件、跨局规则。公共契约见 `contracts/engine-contract.md`；即使某节与 `junk.md`/`bloodbattle.md` 恰好一样，也各写一份，不互相链接（见 `architecture/variant-boundary.md`）。
> v2 补上三牢点炮限制与连庄坐庄（§5/§8）：需要一个跨局状态传递的契约（`dealerStreak`），已在 Room 层落地为通用机制，见 `contracts/session-mechanics.md` §5。

## 1. 牌集与开局

- 136 张：万(m)、筒(p)、条(s) 各 1–9 × 4；风牌东南西北 × 4；箭牌中发白 × 4；无花牌
- 白板固定为财神，身份恒定（不像日麻宝牌指示牌那样逐局变化）
- 4 人；庄家 14 张，闲家 13 张；无换三张、无定缺（与 junk 一致，无前置阶段）
- 随机定座定庄（由 seed 决定，可复现，与 junk/bloodbattle 一致）

## 2. 财神规则

- 财神（白板）可代替任意牌完成胡牌牌型（面子、将、七对子的普通对子）
- 财神不能用于吃、碰、杠——手牌中的白板即使凑够 3/4 张也不能碰/杠，不能用于与他人打出的牌组成吃/碰/杠副露，只能留作胡牌替代
- **打出的财神不能被其他玩家吃、碰、杠、胡**（不能被声明，也不能被点炮）
- **打出财神的当圈限制（打财神/敲响限制）**：
  - 任何玩家打出财神（无论是财飘还是普通打出财神）后，全场进入“当圈限制”状态，持续一圈（直至轮回到打出财神的玩家摸牌前解封）。
  - 在当圈限制期内，**除打出财神的玩家外**，其他玩家：
    - **禁止操作**：吃、碰、明杠（含直杠与加杠/补杠）、放炮（点炮胡他人的打牌）。
    - **允许操作**：自摸胡牌（zimo）、暗杠（anGang）、摸牌后打牌。
    - **摸打限制**：摸牌后**只能打刚摸进的那张牌（摸打/模打）**，不能换牌打出手牌中的其他牌（防止利用该圈调整手牌结构）。
- 财神在手可同时替代多个不同位置，唯一上限是牌墙里总共只有 4 张白板
- **豪华七对子的"四张相同"必须是真实同种牌，不能靠财神凑出第四张**（§6 已用 111 万 + 财神举例说明：只有 3 张真 1 万时不算豪华）——这是财神代替规则的一个例外，仅对"四张相同"这个判定生效，普通对子仍可用财神代替

## 3. 行牌规则

- 摸牌：按逆时针轮转，从牌墙头部摸；与 junk/bloodbattle 一致，core 层是显式 `{type:"draw"}` 动作（见 §9 `awaiting-draw` 相位），谁/何时提交该动作是 server 编排层职责，不属于本文件范围
- 出牌后进入声明窗口，优先级：胡 > 杠 > 碰 > 吃（与 junk 相同的优先级表，各玩法独立定义，见 `architecture/variant-boundary.md`）
  - 吃：仅出牌者的下家可吃
  - 碰/明杠：任意他家
  - 财神不参与被吃/碰/杠/胡（见 §2）
  - 若处于打出财神当圈限制期，除打出财神者外，其余玩家不可响应吃、碰、明杠、放炮（见 §2）
- 自己回合内：可打出、可暗杠、可补杠（碰后摸到第四张）、可自摸胡；若处于打出财神当圈限制期，不可补杠（明杠），打牌只能打刚摸进的牌（摸打/模打）
- 杠后从牌墙尾部补一张（无王牌区，简化处理，同 junk）；补牌后直接胡称为"杠开"，计入 §6 番数表

## 4. 听牌 / 爆头 / 财飘：派生状态

这三者都不是玩家声明，是每次状态转换后根据当前牌型自动判定、只对本人可见的派生字段——其他玩家不知道，直到摊牌结算才揭晓。

- **听牌**（`isTingpai`）：当前手牌已满足"再摸/再碰任意一张合法牌即可胡"的条件（财神可代替）
- **爆头**（`isBaotou`）：同时满足——(a) 已经听牌；(b) 手中持有至少一张财神；(c) 任意摸一张牌都能组成胡牌（不需要挑牌，摸什么都胡）
- **财飘**（`isCaipiao`）：处于爆头状态时，主动打出一张财神，打出后仍然保持爆头，则进入财飘；如果打出财神时未处于爆头状态或打出后不再保持爆头，则仅为普通打出财神（例如残局快抓完牌时打出财神专门限制他人当圈换牌）。不论是否触发财飘，只要打出财神，均触发 §2 的“当圈限制其他玩家吃/碰/明杠/放炮及只能摸打刚摸牌”规则。
- 三者在每次摸牌/出牌/吃/碰/杠之后都要重新计算；不满足条件立即取消，不做"锁定"语义——爆头/财飘状态下依然可以吃/碰/杠，操作后重新判断
- **双财飘/三财飘定义与中断（已确认）**：与"手里同时有几张财神"无关，是本手牌从开局到胡牌为止，"处于爆头状态下主动打出财神、打出后仍保持爆头"这一事件**成功发生的累计次数**（`caiPiaoCount`）。第一次成功即财飘（4 倍）；此后继续摸牌，若再次满足"爆头下打出财神仍保持爆头"，`caiPiaoCount` 累加到 2 记双财飘（8 倍），累加到 3 记三财飘（16 倍）；胡牌结算时按最终 `caiPiaoCount` 取番。**中断条件**：轮到自己回合弃牌时，只要弃出的牌**不是财神**，`caiPiaoCount` 立即清零、后续需重新累计——与弃牌后是否仍保持爆头无关，这是比"是否仍爆头"更严格的中断条件（弃财神但不满足财飘条件的"普通打出财神"不触发清零，因为弃的牌本身仍是财神）。当前实现是"不清零、纯累计"，与本条已不一致，需改代码同步（跟踪见 `docs/process/plan.md`）。

## 5. 三牢点炮规则（已实现）

- 前两庄不能点炮，只能自摸；连续三次坐庄后，进入三牢；三牢状态允许点炮
- 判定用 `dealerStreak`（当前庄家已连续坐了几局，含本局）：`dealerStreak < 3` 时点炮（`hu` 声明）在声明窗口里不作为合法选项，`zimo`（自摸）不受影响；`dealerStreak >= 3` 恢复正常
- `dealerStreak` 不是玩家可配置项，由 Room 层每局注入 `GameConfig`（跨局状态传递机制，见 §8 与 `contracts/session-mechanics.md` §5）；第 1 局（房主坐庄）`dealerStreak=1`
- 流局也算庄家连庄（见 §8），因此流局同样会推进 `dealerStreak`

## 6. 胡牌与番数

- 胡牌结构：4 面子 + 1 对（基本型）或七对；财神可替代任意牌完成上述任一结构
- 可自摸、可点炮胡（点炮受 §5 三牢限制，自摸不受限）
- 一人胡牌，本局立即结束。**一炮多响策略：头跳**（已确认）——只有出牌者逆时针方向最近的可胡家胡牌，与 junk 现状一致

**番数表**（倍数直接相乘，与血战"番数取 2 的幂"的模型不同——这里倍数表本身已经是最终乘数）。牌型分三个番组：**基础型组**、**七对型组**（与基础型组互斥，二选一大类）、**杠型组**（可与前两组里被选中的那一档相乘）：

**基础型组**（互斥，取一档）：

| 类型   | 倍数 |
| ------ | ---: |
| 平胡   |    1 |
| 爆头   |    2 |
| 财飘   |    4 |
| 双财飘 |    8 |
| 三财飘 |   16 |

双财飘/三财飘的精确定义见 §4。

**七对型组**（互斥，取一档；与基础型组二选一，不同时出现）：

| 类型         | 倍数 |
| ------------ | ---: |
| 七对子       |    2 |
| 豪华七对子   |    4 |
| 双豪华七对子 |    8 |
| 三豪华七对子 |   16 |

**豪华七对子定义**（已确认）：七对子本身要求 7 个对子、14 张牌，不含顺子/刻子/杠子。"豪华"指七对里有 `quadCount` 组**真实**四张相同的牌（例如 `1111万 22万 33条 44条 55筒 66筒 东东`，`1111万` 这组四张视为两个对子，不算杠、不需要声明开杠，老实留在手牌里）：`quadCount>=1` 记豪华，`>=2` 记双豪华，`>=3` 记三豪华。四张相同**必须是真实同种牌**，不能靠财神凑出第四张（`111万 + 财神` 不算豪华，因为真实只有 3 张 1 万）；普通对子仍可用财神代替。七对系列要求门清——**若这四张实际被声明为暗杠（移入副露），不再算作七对子的一组对子**（已确认："杠后不算对子，必须保持在手上才算对子"），脱离七对家族判定，改按基础型 + 杠型组计算。

**杠型组**（互斥，取一档；可与基础型组或七对型组的选中档相乘）：

| 类型   | 倍数 |
| ------ | ---: |
| 杠开   |    2 |
| 二连杠 |    4 |
| 三连杠 |    8 |
| 四连杠 |   16 |

**连杠定义**（已确认）：杠型组统计的是"连续开杠链条的长度，且链条最后一次杠后摸到的牌正好是胡的那张"——链条中间的杠不需要自摸，只有链条终点那次摸牌胡牌才计数；杠开是链条长度为 1 的特例。链条长度 2/3/4 分别记二/三/四连杠，四档互斥只取最长命中的一档（不是相互叠加）。

**叠加规则**：基础型组与七对型组二选一，各自内部互斥只取最高命中档；杠型组内部同样互斥只取一档，但可以与前面选中的那一档相乘。例如：爆头(2)×杠开(2)=4 倍（"爆头+杠开"）；财飘(4)×杠开(2)=8 倍（"飘杠"）。

## 7. 计分方式

**支付公式：方案 A（已确认）**——点炮：点炮者单独支付 `底分 × 倍数`；自摸：其余三家各自支付 `底分 × 倍数`（自摸总收益是点炮的 3 倍，与 junk 的支付模型一致，不额外加自摸奖励）。

**底分（已确认）**：`baseScore = 1`，与 junk 一致，不做成可配置项（除非以后有需求再加）。

**庄家连庄倍率（已确认）**：任意一笔涉及庄家的收付——庄家胡牌时别人付给庄家的钱，或庄家点炮/自摸付钱给别家时庄家付的钱——在 §6 番型倍数算完后再乘一档庄家倍率，按 `dealerStreak`（当前庄家已连续坐了几局，含本局）取值：

| `dealerStreak` | 倍率 |
| -------------- | ---: |
| 1              |    2 |
| 2              |    4 |
| ≥3             |    8 |

这是 `dealerStreak` 这一个字段的**第二个独立效果**，与 §5"三牢"（`dealerStreak>=3` 才解锁点炮）是两条不同阈值、不同作用的规则，不要混为一谈：三牢管的是"点炮这个动作合不合法"，这里管的是"钱付多少"，`dealerStreak` 从 1 开始就已经生效庄家倍率（不像三牢要等到第 3 局才生效）。这条倍率与庄家是否胡牌无关——庄家点炮/被自摸时一样要多付。计算上是一笔笔"收付边"各自判断（付款方或收款方只要有一方是庄家就整笔乘倍率），不是对整局分数统一乘——一炮多响时，点炮者如果是庄家，付给每个赢家的那一笔都各自乘倍率；自摸时如果赢家不是庄家、三个付款人里恰好有一个是庄家，只有庄家那一笔翻倍，其余两笔不受影响。`HuDeclared` 事件的 `fanTypes`/`multiplier` 只反映番型本身的倍数，不包含这条庄家倍率（与 `docs/variants/junk.md` §3/§6 的约定一致）；实际到账金额只体现在 `Settled` 的 `scoreDeltas` 里。

## 8. 跨局规则

- **庄家轮换公式**（对应 `contracts/engine-contract.md` §4 的 `computeNextDealer` 契约，已确认）：庄家胡牌（自摸或点炮，包括一炮多响里庄家是其中一个赢家的情况）或流局都连庄；只有别家胡牌（庄家不在赢家之列）时才轮到下一位（逆时针下一座，`nextSeat`）。这与 junk/bloodbattle"不管结果一律顺时针轮转"的实现不同，是本项目第一个连庄玩法——已按 `architecture/variant-boundary.md` §2 的门槛把"庄家轮换公式"这一行转正判定为**确认私有**（junk/bloodbattle 恰好一样只是巧合，杭州证明了差异，因此永久保持各玩法自己实现，不提取公共代码）
- **`dealerStreak` 跨局状态传递**：这是纯编排层的通用机制，不是杭州专属——Room 每局结束后比较"下一局庄家座位"是否等于"上一局庄家座位"，相等则 `dealerStreak += 1`，不等则重置为 1，写入下一局 `GameConfig`；这个比较本身不理解任何麻将规则，只在座位号上做比较，属于"外壳只编排"的范畴（对应 `contracts/session-mechanics.md` §5）。junk/bloodbattle 的 config 里也会收到这个字段，但两者都不读它，行为不受影响
- **会话排名**：复用房间层通用实现（纯分数从高到低排序），同 junk/bloodbattle 现状，见 `contracts/session-mechanics.md` §4

## 9. Phase 与 Action（私有类型，草案）

- `HangzhouPhase`：`dealing → playing ⇄ awaiting-claims ⇄ awaiting-draw → finished`（结构与 junk 相同，见 `junk.md` §5），无前置阶段
- `HangzhouAction`：discard/chi/peng/anGang/buGang/minGang（响应态）/zimo/hu/pass/draw——与 junk 同构，实现时在 `applyAction` 层收紧财神相关的合法性（不可吃/碰/杠财神）
- `HangzhouState` 不需要 junk/bloodbattle 都没有的额外前置阶段字段；需要为 §4 的派生状态在内部状态与 PlayerView 之间维护
- `HangzhouState` 新增私有字段 `dealer`（本局庄家座位，整局固定不变，供 §7 庄家倍率判断"这笔收付是否涉及庄家"用；跨局延续是 `computeNextHangzhouDealer` 的职责，不由这个字段本身表达）——与 `junk.md` §5 新增的同名字段同构

## 10. 事件清单

基础事件集与 junk 的 17 种同构（见 `junk.md` §6），本文件不重复列表；杭州特有的部分：

- `HuDeclared` 携带触发的番型集合（`fanTypes`/`multiplier`，用于结算展示），并额外携带 `winTile`（胡的那张牌，`TileId`）与 `groups`（实际计分用的拆分——4 面子+1 将，或七对型的 7 组，`TileKind[][]`，财神用 `CAISHEN_KIND` 本身占位，不记录"替代了哪张牌"）；`hand` 字段维持既有的完整摊牌不变。分支顺序（门清先试七对再试基本型）与计分逻辑 `evaluateWinningShape` 逐字复刻，保证 `groups` 与 `fanTypes` 出自同一次判定，不存在多解歧义
- 不新增财飘/爆头相关的公开事件——它们是私有派生状态，不广播，只体现在本人 PlayerView 与胡牌结算的番型解释里

## 11. PlayerView 私有/公开字段

`HangzhouPlayerView` 在 `PlayerViewBase` 之上扩展 `phase`/`myActionOptions`/`myClaimOptions`/`lastDiscard`/`justDrawn`/`result`（与 junk 同构字段命名，见 `junk.md` §7），新增杭州专属的：

- `isTingpai: boolean`、`isBaotou: boolean`、`isCaipiao: boolean`——**私有**，仅本人可见，每次状态转换后重算，通过既有的 `LegalActionsUpdated` 同步机制一并下发，不新开事件类型
- `dealerStreak: number`——**公开**，所有座位的 view 都带同一个值；这是全桌可推导的信息（点炮是否开放本就不是秘密，见 §5），不像上面三个是私有派生状态。整局固定不变，`getPlayerView`/`rebuildPlayerView` 都从 `state.config.dealerStreak` 取值
- `dealer: SeatId`——**公开**，本局庄家座位，整局固定，供客户端展示"庄家倍率"提示用；仿 junk.md §7 的同名公开字段
- `seats[i].winSnapshot?: { hand: TileKind[]; winTile: TileKind; groups: TileKind[][] }`——**公开**，仅胡牌那一刻起该座位才有此字段（`state.wins[seat]` 落地时写入，直到整局结束不再清除）；`hand`/`winTile` 在 `HuDeclared`（私有 `TileId`）与 `getPlayerView`/`rebuildPlayerView`（转换成 `TileKind`）之间的边界与 bloodbattle 的 `WinSnapshot`/`PublicWinSnapshot` 做法一致，`groups` 本来就是 kind 级别不需要转换。仿血战到底揭示模式，见 `bloodbattle.md` §10 `HuDeclared`。`hand`/`groups` 的展示排序规范见 `contracts/engine-contract.md` §5。

## 14. 规则拍板记录

Slice 0 需要确认的问题均已拍板：一炮多响策略（头跳）、点炮/自摸支付公式（方案 A，底分 1）、"豪华七对子"定义（真实四张相同计数，财神不能凑第四张，声明暗杠后不再算对子）、"连杠"定义（连续开杠链条长度，终点摸牌即胡）、双/三财飘定义（跨全局累计的"爆头下打财神仍爆头"成功次数，与手里财神张数无关）。

三牢/连庄专题需要确认的问题也已拍板：跨局状态传递架构（Room 层通用比较前后两局庄家座位，结果写进下一局 `GameConfig` 的 `dealerStreak`，不改 `computeNextDealer` 签名）、庄家连庄触发条件（庄家胡牌或流局都连庄，别家胡牌才轮庄）。

庄家连庄倍率专题（v3）已拍板：适用范围是"任意涉及庄家的收付都翻倍"（不只是庄家胡牌那一种情况）；倍率按 `dealerStreak` 取值 1→×2、2→×4、3 及以上→×8 封顶；与 §6 的番型倍数是乘法叠加关系。

打出财神当圈限制专题已拍板：打出财神（白板）不能被他人吃/碰/杠/胡（点炮）；被打出财神后，除出牌者外其余玩家当圈禁止吃、碰、明杠（含加杠）、点炮胡，且摸牌后只能打刚摸进的牌（摸打，不能换手牌结构）。打财神可以单纯用于限制他人换牌（不要求必须为财飘）。

财神数量与 `caiPiaoCount` 清零专题已拍板：财神在手可同时替代多个位置，上限仅为牌墙总共 4 张白板（§2），无额外上限；`caiPiaoCount` 清零规则见 §4——轮到自己弃牌，只要弃的不是财神就清零，与弃牌后是否仍爆头无关。**当前实现与该清零规则不一致（现为不清零纯累计），是待办代码变更，跟踪见 `docs/process/plan.md`。**
