# Junk AI 决策质量优化最终记录

## 目标与最终方案

本轮目标是让 Junk AI 在可控延迟内使用两轮 2-ply 评估，同时保持 core 与 AI 的职责边界清晰。

正式接入的路径为：

1. 用当前基础评分对弃牌排序；
2. 首轮从高分端应用上断崖，固定 `minN=2`、`maxN=4`、阈值 20%；
3. 第二轮从低分端应用下断崖，固定 `minN=1`、`maxN=all`、阈值 20%；
4. 每次摸牌都额外保留刚摸入的牌；
5. 使用 core `evaluateUkeireAfterDiscardDraws` 批量计算弃牌与摸牌后的结构向听；
6. 对首轮候选使用完整 2-ply 叶子评分，选择最终弃牌。

当前基础权重保持不变。权重和断崖参数优化属于关闭本分支后的独立工作，不在本记录中展开。

## Core batch API

`evaluateUkeireAfterDiscardDraws` 是纯结构 API：

```ts
(弃牌种类, 摸牌种类) -> 向听数
```

它不返回概率、番型、AI 权重或最终决策。AI 负责候选筛选、概率和叶子评分，core 只负责通用手牌结构计算。

已验证该矩阵与原有逐状态结构计算逐项一致。完整 2-ply 端到端 benchmark 中：

- 旧结构路径约 `25.33ms/case`；
- core batch 路径约 `22.54ms/case`；
- 约减少 11% 耗时；
- 决策一致率 100%，平均分差为 0。

- 既有副露 ukeire 修复；
- 当前回合结构分析缓存；

- core 两变化结构 batch API；
- 双向相对断崖 2-ply 候选路径；
- 正式路径所需的桥牌、有效进张和默认策略回归测试；
- 通用 arena、权重 A/B、调参和代码版本对比工具。

## 已拒绝或删除的路线

- 固定 Top-1/Top-2/Top-3 直接替代完整候选；
- 结构 Top-4 直接剪枝；
- 最低向听黑名单作为无条件安全剪枝；
- 候选之间共享缓存作为主要优化；
- 候选与摸牌状态统一批处理；
- full-result batch（额外返回 improvingKinds）；
- 仅靠首轮排序固定第二轮 Top-4；
- 独立的 baseline、对抗性搜索和结构 benchmark 工具链。

这些路线的实验过程不再作为仓库维护代码保留；最终结论和必要证据保留在本文件与 `plan.md`。

## 限制

- 2-ply 仍是启发式评估，不是完整牌局价值证明；
- 20% 断崖是当前固定配置，不代表最终最优参数；
- 基础评分权重尚未在本分支内调优；
- core batch 只加速结构层，叶子弃牌评分仍是主要成本；
- 任何后续权重或评分公式变更都必须重新做固定样本和真实 AI A/B。
